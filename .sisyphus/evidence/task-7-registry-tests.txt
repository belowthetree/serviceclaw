## Storage Structure

```
~/.openclaw/services/
├── {serviceId}/
│   ├── manifest.json    # Original service manifest
│   ├── config.json      # User configuration values
│   ├── state.json       # Current state + history
│   └── refs.json        # Runtime references (cronJobIds, webhookPaths, etc.)
└── index.json           # Registry index for fast lookup
```

## Key Types

### ServiceState
- `pending` - Service created but not validated
- `validating` - Checking requirements
- `installing` - Creating resources
- `installed` - Resources created, not running
- `enabled` - Active and processing triggers
- `disabled` - Installed but off
- `error` - Runtime error occurred
- `validation_error` - Requirements not met
- `install_error` - Installation failed
- `uninstalling` - Cleaning up

### ServiceRegistry API

#### CRUD Operations
- `register(manifest, initialConfig)` - Register new service
- `unregister(serviceId)` - Remove service
- `get(serviceId)` - Get service instance
- `exists(serviceId)` - Check if service exists

#### State Management
- `updateState(serviceId, newState, reason)` - Update service state
- `updateConfig(serviceId, config)` - Update configuration
- `validateConfig(serviceId, config)` - Validate configuration
- `enable(serviceId)` / `disable(serviceId)` - Lifecycle helpers

#### Resource Tracking
- `updateRuntimeRefs(serviceId, refs)` - Update runtime references
- `getRuntimeRefs(serviceId)` - Get runtime references

#### Execution Tracking
- `recordSuccess(serviceId)` - Record successful execution
- `recordFailure(serviceId, error)` - Record failed execution
- `updateNextRun(serviceId, nextRunAt)` - Update next run time

#### Querying
- `list(options)` - List services with filtering
- `getByState(state)` - Get services by state
- `getAll()` - Get all full service instances
- `getStats()` - Get registry statistics

#### Persistence
- `recover()` - Rebuild index from disk
- `clear()` - Clear entire registry (testing)

## Error Classes

- `ServiceRegistryError` - Base registry error
- `ServiceNotFoundError` - Service doesn't exist
- `ServiceAlreadyExistsError` - Duplicate service
- `InvalidStateTransitionError` - Invalid state transition

## State Transitions

Valid transitions are enforced:
```
pending → validating, validation_error, uninstalling
validating → installing, validation_error
installing → installed, install_error
installed → enabled, disabled, uninstalling
enabled → disabled, error
disabled → enabled, uninstalling
error → disabled, validating
validation_error → validating, uninstalling
install_error → validating, uninstalling
uninstalling → (removed)
```

## Persistence Patterns

Following existing OpenClaw patterns:
- Uses `fs/promises` for async file operations
- Atomic writes using temp files + rename
- Secure file permissions (0o700 for dirs, 0o600 for files)
- JSON5 for reading (tolerant), JSON for writing
- Cached index for fast lookups
- Recovery mechanism to rebuild from disk
