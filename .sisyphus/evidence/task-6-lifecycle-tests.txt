## Implementation Details

### Service Class Features

1. **State Machine** (10 states):
   - `pending` → `validating` → `installing` → `installed` → `enabled`/`disabled` → `uninstalling`
   - Error states: `validation_error`, `install_error`, `error`
   - Complete state transition validation
   - State history tracking with timestamps

2. **Atomic Installation** (4 phases):
   - Phase 1: Validation (no side effects)
   - Phase 2: Preparation (reversible)
   - Phase 3: Resource Creation (tracked for rollback)
   - Phase 4: Commit
   - Automatic rollback on failure using rollbackStack

3. **Runtime References Tracking**:
   - Cron job IDs with cleanup
   - Webhook paths and unregister functions
   - Message subscriptions with unsubscribe handlers
   - Agent ID and session key management

4. **Trigger Integrations**:
   - **CronService**: Creates jobs with service-scoped IDs (`service:{id}:cron:0`)
   - **Webhook Registry**: Registers HTTP routes with auth support
   - **Hook System**: Subscribes to message events with filter matching

5. **Error Classes**:
   - `ServiceError`: Base error with serviceId and cause
   - `ServiceInstallError`: Includes installation phase
   - `ServiceValidationError`: Includes validation errors array
   - `ServiceStateError`: Includes current and attempted state

### Integration Points

1. **CronService Integration**:
   - Uses `cronService.add()` to create jobs
   - Uses `cronService.remove()` for cleanup
   - Metadata tracking for service ownership

2. **Webhook Registry Integration**:
   - Uses `registerPluginHttpRoute()` for registration
   - Stores unregister functions for cleanup
   - Auth validation support

3. **Hook System Integration**:
   - Uses `registerInternalHook()` for message events
   - Filter matching for keywords, patterns, users
   - Stores unsubscribe functions for cleanup

### Key Design Decisions

1. **Rollback Pattern**: Uses a rollbackStack array that collects cleanup functions during installation. On failure, executes them in reverse order (LIFO).

2. **State Immutability**: Service state can only be changed through validated transitions using `setState()`, which tracks history.

3. **Resource Ownership**: All created resources track their origin (serviceId) for proper cleanup and conflict resolution.

4. **Error Recovery**: Services in error state can transition to disabled and then re-enabled after fixing issues.

5. **JSON Serialization**: `toJSON()` method excludes non-serializable runtime references (functions) for persistence.
